# TapAsk 行为约定

TapAsk 在 Mac 与 Windows 上使用各自的原生实现，两端只共享 `shared/providers.json`、`shared/policy-cases.json` 和本文档。Mac Phase 1 接入 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包；Windows 以下行为均为 **Phase 2 实现**，本仓库当前没有 Windows 程序。

| 行为 | Mac（Phase 1） | Windows（Phase 2 实现） |
| --- | --- | --- |
| 全局快捷键 | ⌥空格，Carbon `RegisterEventHotKey`，只处理按下，无需辅助功能权限 | Phase 2 按同样规则实现 |
| 窗口隐藏时按快捷键 | 激活 app，显示常驻窗口；登录弹窗仍存在时一起显示，并优先让弹窗及其 WebView 获得焦点 | Phase 2 按同样规则实现 |
| 窗口可见时按快捷键 | 不管焦点在 TapAsk 还是下面的 app，按一次就收起：主窗口和登录弹窗一起 `orderOut` 后 `NSApp.hide(nil)`；如果焦点在 TapAsk 上，系统把它还给上一个 app，不自行记录或激活它 | Phase 2 按同样规则实现 |
| 窗口生命周期 | 主窗口启动创建一次；每个服务商独立持有 NavigationPolicy、委托与 WebView，首次使用时才创建并恢复上次页面，无有效记录时加载首页。切换完成后最多保留当前和最近使用的一家主页面；打开第三家时释放最久未用的后台页，后台页从切离时起满 300 秒自动释放，切回取消该页计时，再次切离重新计时。当前服务商即使浮窗隐藏仍保留，当前登录弹窗不受回收影响。切回仍在缓存的已加载会话不重新加载，登录“完成”或后台进程终止标记待刷新的会话除外，失败会话重试首页。自动或手动释放后切回会重新创建会话；登录弹窗按需创建，关闭后清理 | Phase 2 按同样规则实现 |
| 置顶与切换桌面 | `.floating`、`.canJoinAllSpaces`、`.fullScreenAuxiliary`，不随 app 失活隐藏 | Phase 2 按同样规则实现 |
| 窗口外观 | 无显示/隐藏动画，`.fullSizeContentView` 配合隐藏标题与透明标题栏，网页铺到窗口最上沿；保留系统圆角、阴影及拖边缩放，隐藏红绿灯。顶部中央悬浮 36×4pt 白色圆角短条，中心距顶边 12pt，带轻微阴影；不绘制独立底色或分隔线。白条周围 60×20pt 范围显示手形光标并调用 `performDrag(with:)`，拖动后保存位置；其余顶部点击交给网页 | Phase 2 按同样规则实现 |
| 大小与位置 | 默认 480×720，最小 360×480；UserDefaults 保存窗口 frame。保存位置所在屏幕按窗口中心判断；若不在鼠标所在屏幕上，则在该屏幕可用区域居中，保留大小 | Phase 2 按同样规则实现 |
| 隐藏与退出 | ⌥空格 或菜单栏“隐藏 TapAsk”收起主窗口与登录弹窗；Esc 交给网页，网页不处理时忽略，不收起也不响提示音；主浮窗不设 ⌘W。服务商排序窗口使用自己的关闭按钮或 ⌘W 关闭。登录弹窗用“完成，回到主窗口”、关闭按钮或网页的 `window.close()` 关闭，然后把焦点还给主窗口；只有“完成”会请求刷新发起弹窗的服务商；⌘Q 退出 | Phase 2 按同样规则实现 |
| 系统入口 | `LSUIElement` 保持 true，无 Dock 图标；`NSStatusItem` 常驻菜单栏，运行时绘制 22×18pt 单色 template 品牌图标，随系统自动着色；Finder / Spotlight 再次打开时显示窗口 | Phase 2 按同样规则实现 |
| 启动与预热 | 只创建并预热上次使用的服务商；手动打开即显示，后台开始恢复上次页面，无有效记录时加载首页；启动 Apple Event 标记登录项时只预热；已有进程 reopen 时显示当前服务商 | Phase 2 按同样规则实现 |
| 开机自启 | 先将 TapAsk.app 拷进 `/Applications` 再第一次打开，也支持 `~/Applications`；标准化包路径后，仅在这两个目录下且尚未尝试过时记录标记并调用 `SMAppService.mainApp.register()`。其他位置只记 info 日志，不注册、不写标记；注册失败只记日志，之后不覆盖用户的系统设置 | Phase 2 按同样规则实现 |
| 自动更新 | Sparkle 2.10.1 默认每日在后台检查并下载更新；就绪后由独立安装器等待下次正常退出再安装，不主动退出或重启，不中断当前聊天。隐藏浮窗不触发安装。后台提醒只更新菜单状态，不抢焦点；手动“检查更新…”使用 Sparkle 官方界面，用户可选择立即安装并重启。“自动更新”菜单同步控制自动检查与下载，选择由 Sparkle 持久化，启动时不覆盖用户设置。更新保留网站登录数据、服务商排序和窗口偏好；网页草稿、滚动位置及进行中的生成等内存状态不保证在重启后保留 | 待实现 |
| 快捷键冲突 | macOS 不会报告其他 app 注册同一快捷键的冲突，TapAsk 无法检测；若 ⌥空格 没反应或打开了别的 app，请在那个 app 中修改快捷键（常见为 ChatGPT 桌面版的“显示 Mini”）。注册真正失败时，每次启动只提示一次，然后照常显示窗口 | Phase 2 按同样规则实现 |
| 编辑与刷新 | 主菜单支持 ⌘Z、⇧⌘Z、⌘X、⌘C、⌘V、⌘A，View 菜单的 ⌘R 按当前 key window 分配：app 在前台且登录弹窗为 key 时重新 GET 加载经当前 NavigationPolicy 检查的弹窗 initialURL；主窗口为 key、其他窗口为 key 或 app 不在前台时重新加载当前服务商会话。菜单栏菜单的“重新加载”始终作用于当前服务商主页面；主会话失败时加载首页，没有 URL 时走 LastPage 恢复，无有效记录或恢复失败时回退首页 | Phase 2 按同样规则实现 |
| 页面加载 | 主窗口尚无已提交文档时，加载超过 0.4 秒显示转圈与“正在打开”；恢复页面与首页请求超时均为 20 秒。恢复页面使 PageLoadState 进入 failed 时自动回退首页一次，这次失败不显示提示；首页也失败时才显示服务商名称、简短原因和“重试”。按钮加载首页，切回失败会话或再次选择它时自动重试；已提交页面的后续加载失败仅记日志并保留原页面。取消、导航策略中断和交给插件处理不改变加载状态；内容进程终止后，页面显示并开始恢复时重新显示加载提示。提示隐藏时不拦截网页点击；登录弹窗加载与重试规则见下文 | 待实现 |
| 服务商切换 | 默认 ⌘1–⌘6 依次为 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包；主菜单的“服务商”菜单按用户排序后的列表生成，前九项对应 ⌘1–⌘9，菜单 tag 与位置一致。切换时关闭登录弹窗且不恢复旧会话焦点，再将主窗口网页换成目标 WebView 并使其成为第一响应者，透明拖动白条保持在顶部；按目标当前 URL 更新来源胶囊及加载提示并呼出窗口。选择当前服务商同样呼出，保留其登录弹窗，有待刷新标记则恢复加载，失败会话重新加载首页 | Phase 2 按同样规则实现 |
| 服务商记忆 | 每次实际切换写入 UserDefaults 的 `LastProviderID`；启动时恢复该 id，未保存、空值或服务商已移除时退回用户排序后的列表第一项。⌥空格始终显示或收起当前服务商 | Phase 2 按同样规则实现 |
| 页面记忆 | 每家服务商独立保存 `LastPage.<providerID>`；主 WebView 的 didCommit 记录 home 精确主机上的 HTTPS 地址，只保留 scheme、主机、路径。释放前，已提交且不在加载中的主页面再保存一次当前合法地址，覆盖网页内部切换对话但没有 didCommit 的情况；未提交导航、内容进程终止或不合法地址不覆盖旧记录。首次创建会话时按当前 NavigationPolicy 校验并恢复，否则加载首页；登录主机、identityHosts 与弹窗页面不记录 | 待实现 |
| 菜单栏点击与菜单 | 左键单击与 ⌥Space 共用切换逻辑，可见即收起、不可见即呼出；右键或 Control + 左键在图标正下方弹出菜单。菜单按当前状态现生成，依次为“显示 TapAsk”（窗口可见时为“隐藏 TapAsk”）⌥Space、分隔线、按用户顺序排列的服务商（当前项打勾，前九项对应 ⌘1 到 ⌘9）、“服务商排序…”、分隔线、重新加载 ⌘R、释放其他服务商页面、分隔线、检查更新…、自动更新、分隔线、退出 TapAsk ⌘Q。检查更新项按更新状态显示提醒；自动更新项以勾选表示开关。没有其他已创建会话时，释放项置灰。选择服务商同时呼出浮窗；主菜单与菜单栏分别创建菜单项实例。按钮提示为 `TapAsk — 单击呼出，右键菜单`，平时不绑定固定菜单，菜单关闭后清除临时绑定；全局快捷键仍由 Carbon 注册 | Phase 2 按同样规则实现 |
| 释放其他服务商页面 | 手动释放、容量淘汰与 300 秒到期回收共用同一释放路径：先补存合法的当前页面地址，再停止加载、断开回调和代理并移除会话；当前服务商和当前登录弹窗保持不变。仍使用 `WKWebsiteDataStore.default()`，不清 cookie 或其他网站数据、不删除 LastPage。再切回时新建会话并恢复上次页面，无有效记录或恢复失败时回退首页；未发送草稿、滚动位置和进行中的生成等页面内存状态不保留。后台时长使用包含系统睡眠的 ContinuousClock，只有一个到期任务，切换、手动释放及退出会取消或重排任务；显示前再次核对是否到期，不复用已过期的后台页。回收日志只含 reason、provider id 和剩余会话数 | 待实现 |
| 服务商排序 | 从菜单栏“服务商排序…”打开约 300pt 宽的普通窗口，不能缩放，高度容纳全部行；窗口层级高于浮窗，打开时激活 app 并置前，重复打开复用同一个窗口。每行显示灰色拖动图标、灰色 ⌘ 编号及名称，第十项起不显示编号。支持原生整行拖放（仅行间放置）及选中行后 ⌥↑ / ⌥↓，立即保存并重建两个菜单；右下角“恢复默认”删除保存的顺序，关闭按钮或 ⌘W 关闭窗口 | 待实现 |
| 登录与网页数据 | 所有服务商共用 `WKWebsiteDataStore.default()` 持久化数据与修补版 Safari UA，各自保留独立页面状态 | Phase 2 按同样规则实现 |
| 来源提示 | 主窗口在主文档提交后通过 `ProviderSession.title` 更新网页顶部中央的来源胶囊；胶囊距网页顶边 28pt，位于拖动白条下方，半透明深色底、小号文字，`hitTest` 返回 nil，不拦截网页点击；自家 `hosts` 隐藏胶囊。登录弹窗仍在独立窗口标题栏始终显示来源。统一使用 `NavigationPolicy.origin` 的 scheme、ASCII 主机及显式端口，无路径、查询或凭据 | Phase 2 按同样规则实现 |
| 导航提示条 | 主窗口与登录弹窗使用半透明深色底、11pt 小号字的顶部居中提示条，`hitTest` 返回 nil，不拦截点击；主窗口放在来源胶囊下方 6pt，胶囊隐藏时距网页顶边 28pt，避开拖动白条；登录弹窗没有胶囊，距内容顶边 10pt。6 秒后直接消失，无动画；同一窗口、同一主机、同一提示种类 10 秒内只显示一次，重复事件不延长显示或去重时限 | 待实现 |
| 品牌图标 | 菜单栏与 app 图标仅共用 `TapAskCore/BrandMark.swift` 的 CoreGraphics 几何；app 图标使用石墨底板、米白屏幕与琥珀星芒。`Resources/AppIcon.icns` 随仓库保存，`scripts/make-icons.sh` 可重新生成，打包直接复制 | Phase 2 按同样规则实现 |
| 导航与新窗口 | 主窗口与弹窗都检查 action、response 和顶层重定向；主窗口允许的新窗口请求若属于自家 hosts（isProviderURL 为真），直接在主 WebView 加载原请求，不创建弹窗；identityHosts 则使用 WebKit 传入的 configuration 创建独立登录 WebView，保留 window.opener，不替换主页面。同一时间只保留一个弹窗，新登录请求替换旧弹窗；弹窗内再开允许的新窗口时复用当前弹窗。合规外链交默认浏览器，下载及其他请求取消 | Phase 2 按同样规则实现 |
| 附件、权限、下载 | 附件用 NSOpenPanel，遵循多选与目录参数；麦克风/摄像头拒绝；下载取消并记日志 | Phase 2 按同样规则实现 |
| 内容进程终止 | 登录弹窗复用“重试”及 ⌘R 路径，仅以 GET 加载经当前 NavigationPolicy 校验的 initialURL，不重放当前请求；没有可用 initialURL 时不加载，显示失败覆盖层及“请关闭后重新登录”，不提供重试。正在显示的服务商立即重载；后台服务商仅标记待恢复，切回前不重载、不影响当前页面的加载覆盖层。切回后清除标记、开始加载并按通常规则显示加载提示；主窗口隐藏期间的当前服务商也等再次呼出才恢复。主窗口 WebView URL 丢失时经 LastPage 恢复，无有效记录或恢复失败时回退首页；日志仅记录主机名 | Phase 2 按同样规则实现 |

登录弹窗使用独立 NSPanel，默认 480×640，支持拖动和缩放，与主窗口具有相同的置顶、全 Space、全屏辅助及无动画设置。首次显示，以及主窗口换屏后再次呼出时，取主窗口中心点所在屏幕，找不到则用 `NSScreen.main`，按该屏幕的 `visibleFrame` 摆放。优先放在主窗口右侧、顶边对齐、间隔 12pt；右侧放不下则放左侧；左右都放不下则覆盖在主窗口上方，水平居中并保持顶边对齐。最终位置推入可见区域；尺寸超出可见区域时缩小并尽量保留四周各 8pt，宽不小于 360、高不小于 480，屏幕不足最小尺寸时以可见区域为上限。用户手动拖动或缩放后，本次弹窗生命周期内不再自动摆放；关闭后新建的弹窗重新计算。

每次呼出登录弹窗，依次执行激活 app、`makeKeyAndOrderFront`、`makeFirstResponder(webView)`；下一轮 runloop 若弹窗仍可见、app 未隐藏且窗口还不是 key，则按相同顺序补做一次。关闭或隐藏后的延迟回调不会重新显示弹窗。不注入脚本聚焦输入框，网页自行管理字段焦点。

弹窗底部保留 36pt 系统控件工具栏，窗口总高度不变，网页区域相应变矮。左侧次要标签显示当前页面的小写 host，初始取登录入口，之后随主文档提交更新，不含 scheme、端口、路径、查询、片段或凭据；没有 host 时留空。右侧“完成，回到主窗口”按钮由用户主动点击，先复用原有关闭及焦点恢复路径，再对发起此弹窗的服务商主页面刷新一次。若此时已显示另一服务商，则只给原会话标记待刷新，在它下次显示时消费标记并刷新，不影响当前服务商。

弹窗沿用发起会话的 NavigationPolicy、Safari UA 及 WebKit configuration。网页调用 `window.close()` 或用户点击窗口关闭按钮时，清理弹窗并让可见的主窗口及其 WebView 重新获得焦点，不请求刷新主页面；如果整个 app 已收起，则保持隐藏。切换服务商时仍先清理弹窗，不恢复旧会话焦点，再将焦点交给目标 WebView；后台保留的会话不能打开弹窗或更新当前来源胶囊。登录完成可由网页调用 `window.close()` 结束弹窗，也可由用户点击“完成，回到主窗口”，不注入脚本或读取页面内容判断登录结果。

登录弹窗与主窗口复用同一个加载提示覆盖层及 `PageLoadState` 状态机，忽略取消错误 -999 和 WebKit 102/204 对状态的影响。弹窗尚未提交过页面时，加载超过 0.4 秒显示转圈和“正在打开登录页…”；断网、DNS 失败或超时等错误显示“登录页打不开”、简短原因及“重试”。已提交页面之后的导航失败只写日志，保留页面，不显示覆盖层。

导航提示条独立于加载覆盖层，不改变任何导航放行或拦截规则。主框架 action、response、服务器重定向被策略拒绝，以及主框架发起的新窗口被判为 `.cancel` 时，显示“已拦截 <主机>：TapAsk 只在浮窗里打开 <服务商名> 和常见登录页”。点击链接判为 `.browser` 并成功交给系统默认浏览器（包括新窗口链接）时，显示“已在浏览器中打开 <主机>”。提示仅显示小写主机名，不含 scheme、端口、路径、查询、片段或凭据；没有主机的地址不显示。子框架事件、-999、WebKit 102 等加载失败回调、下载（包括最终被取消的下载）、服务商自家页面的新窗口在主浮窗打开、弹窗正常关闭均不显示导航提示。两种提示及不同主机分别去重，主窗口和每个登录弹窗各自计时；后台服务商不能更新当前窗口的提示，切换服务商清掉旧提示但保留该窗口的去重时限，弹窗销毁时取消提示的计时任务。

弹窗“重试”与弹窗为 key 时的 ⌘R 都重新检查创建弹窗时保存的 `initialURL`，仅当它仍通过当前 `NavigationPolicy.isPanelURL` 检查时才新建 GET 请求加载该地址；不重放最后一次请求、POST 请求体或跳转后的 OAuth 一次性回调。没有可用的最初地址时，不显示“重试”，失败提示改为附上“请关闭后重新登录”，弹窗 ⌘R 不加载其他地址。主窗口为 key 或 app 不在前台时，⌘R 仍作用于当前服务商；菜单栏菜单的“重新加载”始终作用于当前服务商主页面。

## 服务商与导航契约

服务商目录及默认顺序来自 `shared/providers.json`，依次为 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包。用户顺序保存在 UserDefaults 的 `ProviderOrder` id 数组中；先按保存顺序排有效 id，忽略已移除或重复的 id，再按目录顺序追加尚未保存的服务商。没有保存顺序或“恢复默认”删掉该键后使用目录顺序。选择按 `LastProviderID` 恢复，没有有效 id 时回退到排序后的第一项；调整排序不切换当前会话、不改变 `LastProviderID`，也不重建 WebView。加载目录时要求至少一个服务商、id 唯一、各服务商 hosts 互不重叠且与 identityHosts 不重叠，主机重叠按大小写归一检查，错误会明确报告。窗口顶层允许的主机等于当前会话服务商 `hosts` 与 `identityHosts` 的并集，大小写归一后精确匹配，不使用后缀匹配。ChatGPT 的五项自家主机及八项共享登录主机保持原样；DeepSeek 仍只包含 `chat.deepseek.com`。四个新增服务商仅加入下表列出的精确主机，不允许 `x.com`、`google.com` 等大站，也不包含豆包裸域 `doubao.com`。`accounts.x.ai` 属于 Grok，自其他服务商程序发起的顶层导航不能在窗口内打开它。Google 跨域登录所需 `accounts.youtube.com` 是独立允许项，不包含普通 YouTube 网页。

| 默认位置 | 服务商 | 首页 | 自家精确主机 |
| --- | --- | --- | --- |
| 1 | ChatGPT | `https://chatgpt.com/` | `chatgpt.com`、`chat.openai.com`、`auth.openai.com`、`auth0.openai.com`、`setup.auth.openai.com` |
| 2 | Claude | `https://claude.ai/` | `claude.ai` |
| 3 | Gemini | `https://gemini.google.com/app` | `gemini.google.com` |
| 4 | DeepSeek | `https://chat.deepseek.com/` | `chat.deepseek.com` |
| 5 | Grok | `https://grok.com/` | `grok.com`、`accounts.x.ai` |
| 6 | 豆包 | `https://www.doubao.com/chat/` | `www.doubao.com` |

六家服务商的打开与登录已于 2026-11-06 由用户真机验收。Grok 另放行自家登录主机 `auth.grok.com`。Google 登录使用现有的 `accounts.google.com`、`accounts.youtube.com`，不扩大共享登录主机；若登录仍有缺失的主机，须依据真机日志确认后再补精确允许项。

HTTPS 检查拒绝凭据、空主机、非 443 显式端口及其他协议。顶层外链只有在来源可信、用户点击且请求为 GET 时才交默认浏览器；脚本跳转、重定向和 POST 不外送。缺失 method 按原策略视为 GET。HTTPS 子框架和 `about:blank` / `about:srcdoc` 按独立分支检查，不扩张顶层信任范围。

页面记忆比自家 hosts 范围更窄，只接受与该服务商 home 主机大小写归一后完全相同、且通过当前 NavigationPolicy 自家页面检查的 HTTPS 地址。例如 ChatGPT 的 `auth.openai.com`、Grok 的 `accounts.x.ai` 和共享 identityHosts 即使允许导航也不记录。记录时去掉查询参数、片段和显式端口，不保存用户名或密码，路径编码保持原样；`https://gemini.google.com/u/1/app?hl=zh` 保存为 `https://gemini.google.com/u/1/app`。恢复时重新执行同样的校验和清理；记录无效或主机已不被允许时加载 home。仅在首次恢复失败时自动回退 home 一次，已有“重试”和 ⌘R 的行为不变。

DeepSeek 的首页、`/sign_in` 及共享登录主机可在窗口内打开；脚本整页跳到 `www.deepseek.com` 或其他服务商主机时取消，合规点击 GET 外链交默认浏览器。`open.weixin.qq.com` 的 HTTPS 内嵌框架按子框架规则允许，不加入顶层信任主机。`chat.deepseek.com` 算作 DeepSeek 自家页面，主窗口来源胶囊隐藏。

`blob:`、`data:` 生成文件及附件仍按原策略返回下载决策，但 app 在 Phase 1 将其取消；不创建下载对象、不保存文件。新窗口回调也服从同样策略，不能绕过点击、请求方法与来源检查。`shared/policy-cases.json` 四组分别表达 `isPanelURL`、`action`、`response`、`origin`，`group` 对应测试，`expected` 为期望值，`excludes` 表达来源不能包含混淆字符。各用例的可选 `provider` 字段选择服务商 id，省略时为 `chatgpt`，未知 id 让测试报错；来源用例的可选 `isProviderURL` 校验是否属于自家页面。

导航日志格式为 `provider=<id> phase=... host=... policy=...`，用 `phase=main-action`、`phase=popup-action` 等阶段区分主窗口和弹窗，包含服务商 id、阶段、主机和策略结果；自家新窗口在主浮窗内打开时用 `phase=main-new-window-inline`，登录弹窗请求保留 `phase=main-new-window`；主窗口加载失败用 `phase=main-fail`，弹窗加载失败用 `phase=popup-fail`，追加错误域 `domain=` 和错误码 `code=`，不记录完整 URL、路径、查询或网页标题。快捷键日志记录到窗口成为 key 的毫秒数；收起只记录 hide。程序不向网页注入脚本，输入框能否自动接收首字仍依赖网页自身焦点行为，必须手动确认。

## 自动更新与分发

app 的 `SUFeedURL` 固定为 `https://github.com/Sure-Will/tap-ask/releases/latest/download/appcast.xml`。发布包包含 Sparkle framework 及安装辅助程序，使用 `SUPublicEDKey` 验证 Ed25519 更新签名，并开启解包前验证。私钥保存在登录钥匙串的 `io.github.sure-will.tap-ask.updates` 账号中，不随源码或更新包分发。每次正式发布递增 `CFBundleVersion`，并将同一批生成的 appcast、DMG、SHA-256 文件完整附加到 Release 草稿，附件核对完成后再发布并设为 Latest。

当前沿用 ad-hoc 签名，没有 Developer ID 或 Apple 公证。构建脚本接受 `CODE_SIGN_IDENTITY`，默认 `-`；仅 ad-hoc 主 app 添加 `com.apple.security.cs.disable-library-validation` entitlement，以允许 Hardened Runtime 加载 Sparkle。更新保留同一 bundle identifier、网站数据和偏好设置，不清理用户数据。编译、签名校验及自动化测试通过不表示自动更新已经完成真机验收。

## 手动验收清单

调试内存时用 `macos/scripts/build-debug-app.sh` 生成独立标识的 `TapAsk-Debug.app`（显示名 TapAsk Debug，偏好与网站数据独立、不注册登录项、快捷键失败只记日志），启动参数 `-TapAskSoak <轮数> [-TapAskSoakDwell <秒数>]` 会按默认每家 8 秒循环切换、轮间开关排序窗口并记录会话数，完成后退出。加上 `-TapAskSoakReleaseOthers YES` 后，循环结束会切到排序后的第一个服务商并释放其他页面一次，记录 `phase=soak release-others before=<释放前会话数> sessions=<剩余会话数>`，再等待一个 dwell 周期后退出，便于采样；未传或传 `NO` 时不执行释放。运行中可用 `macos/scripts/measure-memory.sh TapAsk-Debug [标签]` 分别采样释放前后并追加到 `macos/build/memory.csv`；压测及该参数入口只编译进 DEBUG，release 构建没有此入口。

采样用于活跃网页负载验收；找不到存活的归属 WebKit 进程，或采样中所有 WebKit 进程退出时会明确失败，不把仅主程序的数字写入 CSV。前后对比必须使用同一机器、相同登录与页面负载，并保留终端逐进程输出；未登录调试包结果不能代表正式账号下的占用。
