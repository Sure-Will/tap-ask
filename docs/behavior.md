# TapAsk 行为约定

TapAsk 在 Mac 与 Windows 上使用各自的原生实现，两端只共享 `shared/providers.json`、`shared/policy-cases.json` 和本文档。Mac Phase 1 接入 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包；Windows 以下行为均为 **Phase 2 实现**，本仓库当前没有 Windows 程序。

| 行为 | Mac（Phase 1） | Windows（Phase 2 实现） |
| --- | --- | --- |
| 全局快捷键 | ⌥空格，Carbon `RegisterEventHotKey`，只处理按下，无需辅助功能权限 | Phase 2 按同样规则实现 |
| 窗口隐藏时按快捷键 | 激活 app，显示常驻窗口；登录弹窗仍存在时一起显示，并优先让弹窗及其 WebView 获得焦点 | Phase 2 按同样规则实现 |
| 窗口可见时按快捷键 | 不管焦点在 TapAsk 还是下面的 app，按一次就收起：主窗口和登录弹窗一起 `orderOut` 后 `NSApp.hide(nil)`；如果焦点在 TapAsk 上，系统把它还给上一个 app，不自行记录或激活它 | Phase 2 按同样规则实现 |
| 窗口生命周期 | 主窗口启动创建一次；每个服务商独立持有 NavigationPolicy、委托与 WebView，首次使用时才创建并加载首页，切走后保留页面，不销毁；切回已加载会话不重新加载，失败会话重试首页；登录弹窗按需创建，关闭后清理 | Phase 2 按同样规则实现 |
| 置顶与切换桌面 | `.floating`、`.canJoinAllSpaces`、`.fullScreenAuxiliary`，不随 app 失活隐藏 | Phase 2 按同样规则实现 |
| 窗口外观 | 无显示/隐藏动画，`.fullSizeContentView` 配合隐藏标题与透明标题栏，网页铺到窗口最上沿；保留系统圆角、阴影及拖边缩放，隐藏红绿灯。顶部仅 8pt 透明拖动区调用 `performDrag(with:)`，其余顶部点击交给网页；拖动后保存位置 | Phase 2 按同样规则实现 |
| 大小与位置 | 默认 480×720，最小 360×480；UserDefaults 保存窗口 frame。保存位置所在屏幕按窗口中心判断；若不在鼠标所在屏幕上，则在该屏幕可用区域居中，保留大小 | Phase 2 按同样规则实现 |
| 隐藏与退出 | ⌥空格 或菜单栏“隐藏 TapAsk”收起主窗口与登录弹窗；Esc 交给网页，网页不处理时忽略，不收起也不响提示音；主浮窗不设 ⌘W。服务商排序窗口使用自己的关闭按钮或 ⌘W 关闭。登录弹窗只能用关闭按钮或网页的 `window.close()` 关闭，然后把焦点还给主窗口；⌘Q 退出 | Phase 2 按同样规则实现 |
| 系统入口 | `LSUIElement` 保持 true，无 Dock 图标；`NSStatusItem` 常驻菜单栏，运行时绘制 22×18pt 单色 template 品牌图标，随系统自动着色；Finder / Spotlight 再次打开时显示窗口 | Phase 2 按同样规则实现 |
| 启动与预热 | 只创建并预热上次使用的服务商；手动打开即显示，后台开始加载首页；启动 Apple Event 标记登录项时只预热；已有进程 reopen 时显示当前服务商 | Phase 2 按同样规则实现 |
| 开机自启 | 先将 TapAsk.app 拷进 `/Applications` 再第一次打开，也支持 `~/Applications`；标准化包路径后，仅在这两个目录下且尚未尝试过时记录标记并调用 `SMAppService.mainApp.register()`。其他位置只记 info 日志，不注册、不写标记；注册失败只记日志，之后不覆盖用户的系统设置 | Phase 2 按同样规则实现 |
| 快捷键冲突 | macOS 不会报告其他 app 注册同一快捷键的冲突，TapAsk 无法检测；若 ⌥空格 没反应或打开了别的 app，请在那个 app 中修改快捷键（常见为 ChatGPT 桌面版的“显示 Mini”）。注册真正失败时，每次启动只提示一次，然后照常显示窗口 | Phase 2 按同样规则实现 |
| 编辑与刷新 | 主菜单支持 ⌘Z、⇧⌘Z、⌘X、⌘C、⌘V、⌘A，View 菜单和菜单栏菜单的 ⌘R 重新加载当前会话；失败或没有 URL 时加载该服务商首页 | Phase 2 按同样规则实现 |
| 页面加载 | 主窗口尚无已提交文档时，加载超过 0.4 秒显示转圈与“正在打开”；首页请求超时为 20 秒。失败显示服务商名称、简短原因和“重试”，按钮加载首页，切回失败会话或再次选择它时自动重试；已提交页面的后续加载失败仅记日志并保留原页面。取消、导航策略中断和交给插件处理不改变加载状态；内容进程终止重新显示加载提示。提示隐藏时不拦截网页点击，登录弹窗行为不变 | 待实现 |
| 服务商切换 | 默认 ⌘1–⌘6 依次为 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包；主菜单的“服务商”菜单按用户排序后的列表生成，前九项对应 ⌘1–⌘9，菜单 tag 与位置一致。切换时关闭登录弹窗且不恢复旧会话焦点，再将主窗口 contentView 换成目标 WebView 并使其成为第一响应者，按目标当前 URL 更新来源胶囊及加载提示并呼出窗口；选择当前服务商同样呼出，保留其登录弹窗，只有失败会话重新加载首页 | Phase 2 按同样规则实现 |
| 服务商记忆 | 每次实际切换写入 UserDefaults 的 `LastProviderID`；启动时恢复该 id，未保存、空值或服务商已移除时退回用户排序后的列表第一项。⌥空格始终显示或收起当前服务商 | Phase 2 按同样规则实现 |
| 菜单栏点击与菜单 | 左键单击与 ⌥Space 共用切换逻辑，可见即收起、不可见即呼出；右键或 Control + 左键在图标正下方弹出菜单。菜单按当前状态现生成，依次为“显示 TapAsk”（窗口可见时为“隐藏 TapAsk”）⌥Space、分隔线、按用户顺序排列的服务商（当前项打勾，前九项对应 ⌘1–⌘9）、“服务商排序…”、分隔线、重新加载 ⌘R、分隔线、退出 TapAsk ⌘Q。选择服务商同时呼出浮窗；主菜单与菜单栏分别创建菜单项实例。按钮提示为“TapAsk — 单击呼出，右键菜单”，平时不绑定固定菜单，菜单关闭后清除临时绑定；全局快捷键仍由 Carbon 注册 | Phase 2 按同样规则实现 |
| 服务商排序 | 从菜单栏“服务商排序…”打开约 300pt 宽的普通窗口，不能缩放，高度容纳全部行；窗口层级高于浮窗，打开时激活 app 并置前，重复打开复用同一个窗口。每行显示灰色拖动图标、灰色 ⌘ 编号及名称，第十项起不显示编号。支持原生整行拖放（仅行间放置）及选中行后 ⌥↑ / ⌥↓，立即保存并重建两个菜单；右下角“恢复默认”删除保存的顺序，关闭按钮或 ⌘W 关闭窗口 | 待实现 |
| 登录与网页数据 | 所有服务商共用 `WKWebsiteDataStore.default()` 持久化数据与修补版 Safari UA，各自保留独立页面状态 | Phase 2 按同样规则实现 |
| 来源提示 | 主窗口在主文档提交后通过 `ProviderSession.title` 更新顶部中央的来源胶囊；胶囊距顶边 10pt，半透明深色底、小号文字，`hitTest` 返回 nil，不拦截网页点击；自家 `hosts` 隐藏胶囊。登录弹窗仍在独立窗口标题栏始终显示来源。统一使用 `NavigationPolicy.origin` 的 scheme、ASCII 主机及显式端口，无路径、查询或凭据 | Phase 2 按同样规则实现 |
| 品牌图标 | 菜单栏与 app 图标仅共用 `TapAskCore/BrandMark.swift` 的 CoreGraphics 几何；app 图标使用石墨底板、米白屏幕与琥珀星芒。`Resources/AppIcon.icns` 随仓库保存，`scripts/make-icons.sh` 可重新生成，打包直接复制 | Phase 2 按同样规则实现 |
| 导航与新窗口 | 主窗口与弹窗都检查 action、response 和顶层重定向；允许的 `window.open` 使用 WebKit 传入的 configuration 创建独立登录 WebView，保留 `window.opener`，不替换主页面。同一时间只保留一个弹窗，新请求替换旧弹窗；弹窗内再开允许的新窗口时复用当前弹窗。合规外链交默认浏览器，下载及其他请求取消 | Phase 2 按同样规则实现 |
| 附件、权限、下载 | 附件用 NSOpenPanel，遵循多选与目录参数；麦克风/摄像头拒绝；下载取消并记日志 | Phase 2 按同样规则实现 |
| 内容进程终止 | WebKit 通知内容进程终止时重新加载对应 WebView | Phase 2 按同样规则实现 |

登录弹窗使用独立 NSPanel，默认 480×640，初次显示时在主窗口中央偏上，两者顶边对齐；支持拖动和缩放，与主窗口具有相同的置顶、全 Space、全屏辅助及无动画设置。弹窗沿用发起会话的 NavigationPolicy、Safari UA 及 WebKit configuration。网页调用 `window.close()` 或用户关闭弹窗时，清理弹窗并让可见的主窗口及其 WebView 重新获得焦点；如果整个 app 已收起，则保持隐藏。切换服务商时先清理弹窗，不恢复旧会话焦点，再将焦点交给目标 WebView；后台保留的会话不能打开弹窗或更新当前来源胶囊。登录完成由网页调用 `window.close()` 结束弹窗，不通过注入脚本检测登录结果。

## 服务商与导航契约

服务商目录及默认顺序来自 `shared/providers.json`，依次为 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包。用户顺序保存在 UserDefaults 的 `ProviderOrder` id 数组中；先按保存顺序排有效 id，忽略已移除或重复的 id，再按目录顺序追加尚未保存的服务商。没有保存顺序或“恢复默认”删掉该键后使用目录顺序。选择按 `LastProviderID` 恢复，没有有效 id 时回退到排序后的第一项；调整排序不切换当前会话、不改变 `LastProviderID`，也不重建 WebView。加载目录时要求至少一个服务商、id 唯一、各服务商 hosts 互不重叠且与 identityHosts 不重叠，主机重叠按大小写归一检查，错误会明确报告。窗口顶层允许的主机等于当前会话服务商 `hosts` 与 `identityHosts` 的并集，大小写归一后精确匹配，不使用后缀匹配。ChatGPT 的五项自家主机及八项共享登录主机保持原样；DeepSeek 仍只包含 `chat.deepseek.com`。四个新增服务商仅加入下表列出的精确主机，不允许 `x.com`、`google.com` 等大站，也不包含豆包裸域 `doubao.com`。`accounts.x.ai` 属于 Grok，自其他服务商程序发起的顶层导航不能在窗口内打开它。Google 跨域登录所需 `accounts.youtube.com` 是独立允许项，不包含普通 YouTube 网页。

| 默认位置 | 服务商 | 首页 | 自家精确主机 |
| --- | --- | --- | --- |
| 1 | ChatGPT | `https://chatgpt.com/` | `chatgpt.com`、`chat.openai.com`、`auth.openai.com`、`auth0.openai.com`、`setup.auth.openai.com` |
| 2 | Claude | `https://claude.ai/` | `claude.ai` |
| 3 | Gemini | `https://gemini.google.com/app` | `gemini.google.com` |
| 4 | DeepSeek | `https://chat.deepseek.com/` | `chat.deepseek.com` |
| 5 | Grok | `https://grok.com/` | `grok.com`、`accounts.x.ai` |
| 6 | 豆包 | `https://www.doubao.com/chat/` | `www.doubao.com` |

六家服务商的打开与登录已于 2026-11-06 由用户真机验收。Grok 另放行自家登录主机 `auth.grok.com`。Google 登录使用现有的 `accounts.google.com`、`accounts.youtube.com`，不扩大共享登录主机；若登录仍有缺失的主机，须依据真机日志确认后再补精确允许项。

HTTPS 检查拒绝凭据、空主机、非 443 显式端口及其他协议。顶层外链只有在来源可信、用户点击且请求为 GET 时才交默认浏览器；脚本跳转、重定向和 POST 不外送。缺失 method 按原策略视为 GET。HTTPS 子框架和 `about:blank` / `about:srcdoc` 按独立分支检查，不扩张顶层信任范围。

DeepSeek 的首页、`/sign_in` 及共享登录主机可在窗口内打开；脚本整页跳到 `www.deepseek.com` 或其他服务商主机时取消，合规点击 GET 外链交默认浏览器。`open.weixin.qq.com` 的 HTTPS 内嵌框架按子框架规则允许，不加入顶层信任主机。`chat.deepseek.com` 算作 DeepSeek 自家页面，主窗口来源胶囊隐藏。

`blob:`、`data:` 生成文件及附件仍按原策略返回下载决策，但 app 在 Phase 1 将其取消；不创建下载对象、不保存文件。新窗口回调也服从同样策略，不能绕过点击、请求方法与来源检查。`shared/policy-cases.json` 四组分别表达 `isPanelURL`、`action`、`response`、`origin`，`group` 对应测试，`expected` 为期望值，`excludes` 表达来源不能包含混淆字符。各用例的可选 `provider` 字段选择服务商 id，省略时为 `chatgpt`，未知 id 让测试报错；来源用例的可选 `isProviderURL` 校验是否属于自家页面。

导航日志格式为 `provider=<id> phase=... host=... policy=...`，用 `phase=main-action`、`phase=popup-action` 等阶段区分主窗口和弹窗，包含服务商 id、阶段、主机和策略结果；主窗口加载失败用 `phase=main-fail`，追加错误域 `domain=` 和错误码 `code=`，不记录完整 URL、路径、查询或网页标题。快捷键日志记录到窗口成为 key 的毫秒数；收起只记录 hide。程序不向网页注入脚本，输入框能否自动接收首字仍依赖网页自身焦点行为，必须手动确认。

## 手动验收清单

以下项目需要用户实际运行产物；编译与自动化测试通过不表示已经完成这些验收。

- [ ] 从别的 app 按 ⌥空格，窗口出现，可以直接打字，第一个字不丢。
- [ ] 中文输入法候选框正常，不被浮窗遮挡或抢走焦点。
- [ ] 再按一次收起，焦点和光标回到原来的 app。
- [ ] 连按 10 次不闪白、不卡顿、状态不乱；可检查 `hotkey` 日志延迟。
- [ ] 登录项后台启动并完成预热后第一次按快捷键，页面已经加载好。
- [ ] 收起再呼出，仍然是同一段对话。
- [ ] 退出重开仍然登录着。
- [ ] Google 登录出现一个始终显示当前来源的临时窗口，可直接输入；主页面保持原状，登录完成后弹窗自动关闭，主窗口恢复焦点；邮箱登录仍可用。
- [ ] 主窗口只有离开服务商自家主机时才在顶部中央显示来源胶囊，返回自家主机后隐藏；胶囊下面的网页控件仍能点击。登录弹窗即使回到服务商自家主机也始终在标题栏显示来源。
- [ ] 登录弹窗为 key 时按 ⌥空格，两个窗口一起收起并归还原 app 焦点；再次呼出时原弹窗仍在，并优先获得输入焦点。
- [ ] 用关闭按钮关闭弹窗，主窗口及其 WebView 恢复焦点；在弹窗里按 Esc、⌘W 不会关闭它；再次发起登录可正常打开新弹窗。
- [ ] 再次从主页面请求登录只留下一个弹窗，旧弹窗已关闭；弹窗内再次请求允许的新窗口时复用当前弹窗，不出现第三个窗口。
- [ ] ⌘C、⌘V、⌘Z、⌘A 正常，同时检查剪切和重做。
- [ ] 默认 ⌘1–⌘6 依次切换 ChatGPT、Claude、Gemini、DeepSeek、Grok、豆包，主菜单“服务商”和菜单栏菜单的勾选始终对应当前服务商；⌘7–⌘9 在没有对应服务商时不触发切换。
- [ ] 网页铺到最上沿；默认 480×720 和最小 360×480 窗口下，各服务商顶部侧边栏、新建对话按钮都能点击（顶部 8pt 拖动区除外）。
- [ ] 从窗口顶部 8pt 透明区域拖动，整窗跟随，松开后位置被保存；拖边改大小仍有效，圆角和阴影正常，网页其他区域不拖动窗口。
- [ ] 左键单击菜单栏图标：浮窗不可见时呼出，可见时收起；连续单击与 ⌥Space 的行为一致，不弹菜单。
- [ ] 右键单击、Control + 左键单击均在图标正下方弹菜单，依次为显示 / 隐藏 TapAsk ⌥Space、分隔线、六个服务商及 ⌘1–⌘6、“服务商排序…”、分隔线、重新加载 ⌘R、分隔线、退出 TapAsk ⌘Q；文字、勾选与当前状态一致，每项均可用。关闭菜单后左键仍能直接切换浮窗。
- [ ] 打开“服务商排序…”后窗口盖在浮窗之上并获得焦点，六行完整可见，不能缩放；重复打开只保留同一个窗口。用关闭按钮或 ⌘W 能关闭它，浮窗的 ⌘W 规则不变。
- [ ] 拖动整行到上方、下方和末尾，松手后选中行跟随服务商、⌘ 编号立即刷新；主菜单与菜单栏顺序及快捷键同步变化，勾选仍是原服务商，各自对话保留。
- [ ] 选中一行后按 ⌥↑ / ⌥↓ 能上下移动，首行向上、末行向下保持不动；关闭重开排序窗口、退出重启 app 后顺序保留。
