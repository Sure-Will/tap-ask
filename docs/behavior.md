# tap-ask 行为约定

TapAsk 在 Mac 与 Windows 上使用各自的原生实现，两端只共享 `shared/providers.json`、`shared/policy-cases.json` 和本文档。Mac Phase 1 接入 ChatGPT；Windows 以下行为均为 **Phase 2 实现**，本仓库当前没有 Windows 程序。

| 行为 | Mac（Phase 1） | Windows（Phase 2 实现） |
| --- | --- | --- |
| 全局快捷键 | ⌥空格，Carbon `RegisterEventHotKey`，只处理按下，无需辅助功能权限 | Alt+空格，`RegisterHotKey` + `MOD_NOREPEAT`，不重复触发 |
| 窗口隐藏时按快捷键 | 激活 app，显示常驻窗口；登录弹窗仍存在时一起显示，并优先让弹窗及其 WebView 获得焦点 | 激活 app，显示窗口，让 WebView2 获得焦点 |
| 窗口可见时按快捷键 | 不管焦点在 TapAsk 还是下面的 app，按一次就收起：主窗口和登录弹窗一起 `orderOut` 后 `NSApp.hide(nil)`；如果焦点在 TapAsk 上，系统把它还给上一个 app，不自行记录或激活它 | 不管焦点在哪，按一次就隐藏窗口，让系统把焦点还给上一个窗口 |
| 窗口生命周期 | 主窗口启动创建一次，之后只显示、隐藏，WebView 和会话一直保留；登录弹窗按需创建，关闭后清理 | 同样保留窗口与 WebView2 |
| 置顶与切换桌面 | `.floating`、`.canJoinAllSpaces`、`.fullScreenAuxiliary`，不随 app 失活隐藏 | 原生置顶浮窗，并对齐多桌面体验 |
| 窗口外观 | 无显示/隐藏动画，窄标准透明标题栏可拖动，隐藏红绿灯，可拖边缘缩放 | 原生可拖动、可缩放的简洁浮窗，无显示/隐藏动画 |
| 大小与位置 | 默认 480×720，最小 360×480；UserDefaults 保存窗口 frame。保存位置所在屏幕按窗口中心判断；若不在鼠标所在屏幕上，则在该屏幕可用区域居中，保留大小 | 同样保存位置、大小并跟随鼠标所在屏幕 |
| 隐藏与退出 | 只有 ⌥空格 收起主窗口；Esc 交给网页，网页不处理时忽略，不收起也不响提示音；不设 ⌘W。登录弹窗只能用关闭按钮或网页的 `window.close()` 关闭，然后把焦点还给主窗口；⌘Q 退出 | 只有 Alt+空格 收起；Esc 交给网页，不设关闭快捷键；系统关闭行为按同样原则保留常驻窗口，提供退出命令 |
| 系统入口 | `LSUIElement`，无 Dock 图标、无菜单栏状态图标；Finder / Spotlight 再次打开时显示窗口 | 没有任务栏图标，不出现在 Alt+Tab |
| 启动与预热 | 手动打开即显示，后台开始加载首页；启动 Apple Event 标记登录项时只预热；已有进程 reopen 时显示 | 手动打开显示，作为启动项自启时只预热 |
| 开机自启 | 先将 TapAsk.app 拷进 `/Applications` 再第一次打开，也支持 `~/Applications`；标准化包路径后，仅在这两个目录下且尚未尝试过时记录标记并调用 `SMAppService.mainApp.register()`。其他位置只记 info 日志，不注册、不写标记；注册失败只记日志，之后不覆盖用户的系统设置 | 注册启动项，之后尊重用户在系统中关闭自启 |
| 快捷键冲突 | macOS 不会报告其他 app 注册同一快捷键的冲突，TapAsk 无法检测；若 ⌥空格 没反应或打开了别的 app，请在那个 app 中修改快捷键（常见为 ChatGPT 桌面版的“显示 Mini”）。注册真正失败时，每次启动只提示一次，然后照常显示窗口 | 提示占用并保留可使用的窗口，不改其他 app 设置 |
| 编辑与刷新 | 主菜单支持 ⌘Z、⇧⌘Z、⌘X、⌘C、⌘V、⌘A，View 菜单 ⌘R；保留 ⌘1–⌘9 | 使用对应的原生编辑与刷新快捷键，保留服务商快捷键位置 |
| 登录与网页数据 | `WKWebsiteDataStore.default()` 持久化，使用修补版 Safari UA | 持久化 WebView2 profile |
| 来源提示 | 主窗口在主文档提交后更新标题，自家 `hosts` 留空；登录弹窗始终显示来源。统一使用 `NavigationPolicy.origin` 的 scheme、ASCII 主机及显式端口，无路径、查询或凭据 | 使用相同来源规则 |
| 导航与新窗口 | 主窗口与弹窗都检查 action、response 和顶层重定向；允许的 `window.open` 使用 WebKit 传入的 configuration 创建独立登录 WebView，保留 `window.opener`，不替换主页面。同一时间只保留一个弹窗，新请求替换旧弹窗；弹窗内再开允许的新窗口时复用当前弹窗。合规外链交默认浏览器，下载及其他请求取消 | 按共享用例实现对应的导航和新窗口检查 |
| 附件、权限、下载 | 附件用 NSOpenPanel，遵循多选与目录参数；麦克风/摄像头拒绝；下载取消并记日志 | 对应系统文件选择器与相同 Phase 1 限制 |
| 内容进程终止 | WebKit 通知内容进程终止时重新加载对应 WebView | 对应处理 WebView2 内容进程终止 |

登录弹窗使用独立 NSPanel，默认 480×640，初次显示时在主窗口中央偏上，两者顶边对齐；支持拖动和缩放，与主窗口具有相同的置顶、全 Space、全屏辅助及无动画设置。主窗口与弹窗共用 Safari UA 和导航规则。网页调用 `window.close()` 或用户关闭弹窗时，清理弹窗并让可见的主窗口及其 WebView 重新获得焦点；如果整个 app 已收起，则保持隐藏。登录完成由网页调用 `window.close()` 结束弹窗，不通过注入脚本检测登录结果。

## 服务商与导航契约

当前使用 JSON 中第一个服务商，无切换界面。窗口顶层允许的主机等于该服务商 `hosts` 与 `identityHosts` 的并集，大小写归一后精确匹配，不使用后缀匹配；主机数据保留修补版全部 13 项。Google 跨域登录所需 `accounts.youtube.com` 是独立允许项，不包含普通 YouTube 网页。

HTTPS 检查拒绝凭据、空主机、非 443 显式端口及其他协议。顶层外链只有在来源可信、用户点击且请求为 GET 时才交默认浏览器；脚本跳转、重定向和 POST 不外送。缺失 method 按原策略视为 GET。HTTPS 子框架和 `about:blank` / `about:srcdoc` 按独立分支检查，不扩张顶层信任范围。

`blob:`、`data:` 生成文件及附件仍按原策略返回下载决策，但 app 在 Phase 1 将其取消；不创建下载对象、不保存文件。新窗口回调也服从同样策略，不能绕过点击、请求方法与来源检查。`shared/policy-cases.json` 四组分别表达 `isPanelURL`、`action`、`response`、`origin`，`group` 对应原测试，`expected` 为期望值，`excludes` 表达来源不能包含混淆字符。

导航日志用 `phase=main-action`、`phase=popup-action` 等阶段区分主窗口和弹窗，只包含阶段、主机和策略结果，不记录完整 URL、路径、查询或网页标题。快捷键日志记录到窗口成为 key 的毫秒数；收起只记录 hide。程序不向网页注入脚本，输入框能否自动接收首字仍依赖网页自身焦点行为，必须手动确认。

## 手动验收清单

以下项目需要用户实际运行产物；编译与自动化测试通过不表示已经完成这些验收。

- [ ] 从别的 app 按 ⌥空格，窗口出现，可以直接打字，第一个字不丢。
- [ ] 中文输入法候选框正常，不被浮窗遮挡或抢走焦点。
- [ ] 再按一次收起，焦点和光标回到原来的 app。
- [ ] 窗口开着但被别的 app 抢了焦点时，按 ⌥空格拿回焦点，不收起。
- [ ] 连按 10 次不闪白、不卡顿、状态不乱；可检查 `hotkey` 日志延迟。
- [ ] 登录项后台启动并完成预热后第一次按快捷键，页面已经加载好。
- [ ] 收起再呼出，仍然是同一段对话。
- [ ] 退出重开仍然登录着。
- [ ] Google 登录出现一个始终显示当前来源的临时窗口，可直接输入；主页面保持原状，登录完成后弹窗自动关闭，主窗口恢复焦点；邮箱登录仍可用。
- [ ] 主窗口离开服务商自家主机时显示来源，返回自家主机后清空；登录弹窗即使回到服务商自家主机也始终显示来源。
- [ ] 登录弹窗为 key 时按 ⌥空格，两个窗口一起收起并归还原 app 焦点；再次呼出时原弹窗仍在，并优先获得输入焦点。
- [ ] 用关闭按钮关闭弹窗，主窗口及其 WebView 恢复焦点；在弹窗里按 Esc、⌘W 不会关闭它；再次发起登录可正常打开新弹窗。
- [ ] 再次从主页面请求登录只留下一个弹窗，旧弹窗已关闭；弹窗内再次请求允许的新窗口时复用当前弹窗，不出现第三个窗口。
- [ ] ⌘C、⌘V、⌘Z、⌘A 正常，同时检查剪切和重做。
- [ ] ⌘R 能重新加载，⌘1–⌘9 未被应用占用。
- [ ] 附件按钮能选文件，并按网页要求支持多选。
- [ ] 能在全屏 app 上面呼出，跨 Space 仍置顶。
- [ ] 回答及弹窗里的合规外部链接用默认浏览器打开；非允许主机的脚本跳转被取消，主窗口和弹窗都不加载该页面。
- [ ] 窗口置顶但焦点在下面的 app 时，按一次 ⌥空格 就收起；Esc 和 ⌘W 都不收起窗口；⌘Q 退出。
- [ ] 拖动、缩放、退出重开后保持尺寸；鼠标换屏后从隐藏状态呼出，在目标屏幕居中且大小不变。
- [ ] 手动启动显示窗口；已运行时从 Finder / Spotlight 再次打开显示窗口。
- [ ] 先把 TapAsk.app 拷进 `/Applications`（或 `~/Applications`）再第一次打开，确认注册登录项；重启电脑登录后自动在后台运行，但不弹出窗口。
- [ ] 在尚未尝试注册的状态下从构建目录打开，不注册登录项、不写入 `LoginItemRegistrationAttempted`，只记 info 日志；退出并拷进安装目录后首次打开仍会注册。
- [ ] 在“系统设置 › 登录项”关闭 TapAsk 后，再次手动打开不会重新启用自启。
- [ ] macOS 不会报告跨 app 的快捷键冲突；若 ⌥空格 没反应或打开了别的 app，在那个 app 中修改快捷键（如 ChatGPT 桌面版的“显示 Mini”）后再验证；注册真正失败时，每次启动只提示一次，之后仍显示窗口。
- [ ] 没有 Dock 或菜单栏状态图标；麦克风、摄像头不可用；下载被取消且有日志。
